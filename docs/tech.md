# 历史案例标注平台技术规格

## 1. 架构与交付边界

本规格实现[产品需求](prd.md)定义的 DOCX 导入、切片编辑、多对多标注、案例发布与撤回、检索验证对话框和只读检索 API。平台在 `dataset` 仓库内独立构建和部署。Phase 2 的实际接入在平台完成基线测评后另行实施。

| 组件 | 技术与职责 |
| --- | --- |
| Web | React + TypeScript。提供文档导入、切片浏览与编辑、双栏标注、案例管理和检索验证 |
| API | Node.js + TypeScript + Fastify。处理上传、文档解析、标注事务和统一检索，使用 `pg` 连接数据库 |
| 数据库 | 独立 PostgreSQL，启用 pgvector。保存文档元数据、切片、案例关联及全文和向量索引 |
| 文档存储 | 应用管理的持久化目录，按文档 UUID 隔离，保留原始 DOCX 和结构产物 |
| 向量模型 | 内网 BGE-M3，由 Fastify 通过 OpenAI 兼容接口调用 |

## 2. DOCX 解析与切片

### 2.1 迁移 Phase 2 解析逻辑

迁移基线为主仓库的 [Phase 2 解析说明](../../docs/phase2-parsing.md)及对应源码。在 `dataset` 内复制 DOCX 解析算法及必要测试，记录上游文件和提交号。保留单文档处理链路，导入时由上传者选择源文档或人工测试需求，平台直接处理该文档。

1. 从 `docx-heading-numbering.ts` 和 `docx-heading-resolver.ts` 迁入 Mammoth 文本转换、OOXML 标题识别和自动编号恢复。保留中文标题、附录、显式编号优先、目录及列表抑制逻辑。
2. 从 `filldata-parser.ts` 迁入 DOCX 文本清洗、`parseSegments` 和必要的辅助函数。DOCX 保留标题前正文，按有效标题边界生成初始章节。
3. 迁入 `document-structure-artifact.ts` 及其 DOCX ZIP、Word XML 清洗和表格处理依赖。对齐原始 OOXML 正文与表格，保留章节 ID 冲突修正、层级路径重建、表格归属和结构告警。
4. 以 Node.js ESM 运行，通过 `createRequire` 适配现有 Mammoth CommonJS 内部模块加载，锁定经过回归验证的 Mammoth 版本。解析入口接收平台存储的文件路径，由 Fastify 处理上传与错误映射。迁移范围限于 DOCX 解析与测试，平台运行只依赖自身部署组件。

### 2.2 原始产物与标注切片

- 每个文档保存原始 DOCX 和 `document-structure.json`。结构保留 `sections`、`warnings` 及章节的 `section_id`、`source_ref`、`level`、`section_path_ids`、`section_path_titles`、`text` 和 `tables`。对外出处使用文档 ID、显示名称和章节引用，存储路径仅供服务端使用。
- 在结构处理中保留顶层 OOXML 正文块的原始顺序及章节归属。正文默认每个非空段落一条切片，有明确条款边界时将该条款的正文归入同一切片。表格单独生成一条切片，按原顺序插入所属章节。表格索引文本按行组织，保留列标题与单元格内容的对应关系。
- 无标题文档的正文放入前置章节并照常切片。重复章节 ID 采用规范化结构分配的 ID。解析告警在文档详情中展示，切片可成功生成时允许继续标注。
- 切片编辑保存到 PostgreSQL，原始产物用于回查。损坏、超限或没有可用文本的 DOCX 导入失败并返回原因。上传先写临时目录，解析成功后落盘并写入文档及切片记录，失败时清理此次上传的文件并回滚数据库写入。上传大小和解压后总大小由服务端配置限制。

## 3. 数据模型与标注流程

| 实体 | 核心字段与约束 |
| --- | --- |
| `documents` | UUID、类型 `source / test_requirement`、显示名称、原始文件及结构产物存储键、导入时间 |
| `slices` | UUID、文档 ID、章节 ID 和路径、来源引用、章节内顺序、类型 `paragraph / clause / table`、可编辑文本、更新版本。源切片另外保存关键词索引及按需生成的向量 |
| `cases` | UUID、状态 `draft / published / withdrawn`、可选标注说明、更新版本和时间 |
| `case_slices` | 案例 ID、切片 ID，联合唯一。通过切片所属文档确定源侧或测试需求侧。同一切片可关联多个案例 |

双栏界面按文档和章节浏览切片，选中内容汇总到当前草稿。导入的人工测试需求可立即选择。草稿可保存未完成的配对。发布时校验两侧各至少一条切片，并为尚无有效向量的源切片生成向量。写入索引和变更发布状态在同一数据库事务中提交。撤回以案例状态为准，查询从已发布案例的关联关系构造候选集，因此共享切片仍可服务其他已发布案例。

编辑已发布案例引用的源切片时，先调用模型获取新向量，再在事务中一起写入新文本、关键词索引和向量。模型失败时保留旧文本与旧索引。发布与源切片编辑事务均按切片 ID 顺序锁定涉及的源切片行，再复核版本。编辑提交前复核发布引用状态，若切片刚被发布且当前编辑结果缺少新向量，返回冲突并要求重试。未发布源切片的文本变更使旧向量失效，发布时按当前文本生成向量。测试需求侧编辑只更新关联结果中的展示内容。

## 4. 混合检索

### 4.1 向量与关键词

- Fastify 调用配置地址下的 `POST /v1/embeddings`，传入模型名和输入文本。批量响应按 `index` 还原输入顺序，校验返回条数及向量维度，拒绝非有限值和零向量。BGE-M3 默认按 1024 维配置，部署时用内网实例响应验证。切换模型或维度需先重建源切片向量，再切换查询配置。[BGE-M3 模型卡](https://huggingface.co/BAAI/bge-m3)
- 关键词路对中文显式分词，用 PostgreSQL `simple` 配置构造 `tsvector` 并建立 GIN 索引。额外保留规范化的报文 ID、接口名和字段名完整匹配。索引和查询使用相同的分词与规范化规则。全文匹配按词项相关度排序，完整技术标识命中优先。
- 语义路用 pgvector 的余弦距离排序，首版在符合发布资格的切片上做精确搜索。按实测延迟决定是否启用 HNSW。[pgvector](https://github.com/pgvector/pgvector)

### 4.2 候选过滤与案例排序

1. 两路只召回被已发布案例引用的源切片。关键词路要求满足关键词或技术标识匹配规则，语义路应用可配置的最低余弦相似度。使用标注查询集校准语义门槛和候选池大小。两路过滤后均无候选时返回空列表。
2. 按切片 ID 用 RRF 合并两路排名。每路按照排名贡献 `1 / (60 + rank)`，排名从 1 开始，未出现在该路的切片贡献为零。同分切片按 ID 稳定排序。
3. 将命中切片映射到已发布案例，案例按最高排名的命中切片排序，同分按案例 ID 排序。每个案例只占一个结果名额，默认最多五条。返回每个案例的命中源切片、关联的全部测试需求切片和各自出处。

## 5. API 与部署

文档 API 支持按类型上传 DOCX、查看导入结果及切片、更新切片。案例 API 支持列表、创建、保存草稿、发布和撤回。检索对话框和后续 Phase 2 调用同一个只读接口。

| 契约 | 约定 |
| --- | --- |
| 请求 | `POST /api/v1/search`，JSON 字段 `query` 为去除首尾空白后非空的字符串，`limit` 为可选正整数，默认 5 |
| 成功 | `200`，响应 `{ results: [{ caseId, matchedSourceSlices, testRequirementSlices }] }`。每个切片包含 `sliceId`、`text`、`documentId`、`documentName`、`sectionPath` 和 `sourceRef` |
| 无匹配 | `200`，`results` 为空数组 |
| 无效请求 | `400`，返回错误码及校验失败说明 |
| 模型不可用 | `503`，返回可重试的模型服务错误。超时或不符合向量契约的响应按服务故障处理 |

对话框展示命中源切片、对应测试需求及出处，并区分无匹配、输入错误和服务故障。失败后保留查询文本。未来 Phase 2 查询空结果或遇到服务异常时继续现有生成流程。

部署提供独立的 Web、Fastify 和 PostgreSQL/pgvector 运行环境。数据库启用 `vector` 扩展并执行平台迁移，数据库和文档目录分别持久化。服务端配置 `DATABASE_URL`、文档目录、`EMBEDDING_BASE_URL`（含 `/v1`）、`EMBEDDING_MODEL`、可选 `EMBEDDING_API_KEY`、请求超时和预期向量维度。Web 通过同源 API 请求，模型凭据保留在服务端。

## 6. 验收与基线测评

- **解析一致性**。使用同一批 DOCX 对照 Phase 2 结构结果，核对自动编号、附录、目录过滤、重复 ID、章节路径、合并单元格和表格归属。用正文与表格交错样本验证切片顺序。另测无标题、损坏和无可用文本三类文档。
- **标注闭环**。用两个源切片和三个测试需求切片发布案例，分别以两个源切片查询，均能返回同一案例及全部测试需求和出处。覆盖切片复用、空说明、未满足发布条件、撤回共享切片关联和已发布源切片更新失败。
- **接口与独立运行**。在两套现有系统均未启动时完成导入、编辑、标注、发布和查询。对同一数据库状态验证对话框与 API 的结果和顺序一致，覆盖空输入、无匹配、模型超时、响应维度错误和服务恢复。
- **检索效果**。用同一人工标注集对比纯关键词、纯语义和混合检索，覆盖同义改写、精确技术标识、接口描述、关键数值或单位差异及无匹配查询。记录前五条命中率、无匹配误返回率和代表性失败样例。首轮基线测评后确定 Phase 2 接入门槛。
