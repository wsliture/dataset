# 历史数据集离线原型

在 Edge、Chrome 或 Firefox 中打开 [index.html](index.html)。原型从浏览器本地存储恢复数据，首次打开时载入 CNAS 样例。界面参考 [原始页面](../index.html)，正式版约定见 [产品需求](../prd.md) 和 [技术规格](../tech.md)。

| 入口 | 操作 |
| --- | --- |
| 历史数据集 | 新建数据集时填写名称，可选填备注。确认后可永久删除数据集及其文档、案例和历史 |
| 文档管理 | 在「源需求／设计资料」和「人工测试需求」卡片分别选择 DOCX。模拟上传检查扩展名、大小、数量及同名文件。用内置的 CNAS 摘录查看文档结构 |
| 标注工作台 | 分别从左右栏选择段落或表格内容。填写标题、测试对象和测试类别，预览配对并保存草稿。人工确认要求两侧均有片段 |
| 案例列表 | 按标题、原文、状态、类别、测试对象、接口类型、场景及日期筛选，查看详情，编辑或停用案例，导出有效的已确认案例 |
| 案例检索 | 从顶部进入独立聊天页，输入源需求、设计描述或接口标识。可连续检索，结果展示数据集、命中的源片段、全部关联测试需求、文档名、章节及定位 |

模拟上传记录仅包含文件信息和演示状态。页面使用预置摘录展示文档与标注。检索在本地匹配源侧正文及表格内容，优先查找完整标识或短语，再按英文词项和中文双字命中排序。每个案例合并为一条结果，最多返回五条。只有使用中数据集的已确认有效案例参与检索。

## 原型文件分工

| 文件 | 当前职责 |
| --- | --- |
| [index.html](index.html) | 布局、主体样式、内置 CNAS 样例，以及数据集、文档、标注和案例列表的交互与本地存储 |
| [app.js](app.js) | 本地案例检索、连续查询、结果卡片，以及删除数据集后清理对应结果 |
| [styles.css](styles.css) | 顶部导航和独立检索聊天页的样式 |

打开 HTML 时浏览器会加载另外两个文件。复制离线原型时应将三者放在同一目录。

## 迁移到 React Web

在 dataset 仓库新增 `web/`，使用 Vite、React 和 TypeScript 构建。现有离线原型可作为界面对照和模拟演示入口。正式版的接口、DOCX 解析和混合检索以[技术规格](../tech.md)为准。

### 1. 建立路由和组件

| 路由 | 页面与交互 |
| --- | --- |
| `/datasets` | 统计卡片、关键词查询和数据集表格。通过操作栏打开、编辑和删除；新建及编辑共用名称必填、备注选填的表单 |
| `/datasets/:datasetId/documents` | 分栏管理源需求／设计资料和人工测试需求。提供 DOCX 上传、结构预览、解析反馈和删除 |
| `/datasets/:datasetId/annotation` | 双栏独立选择文档与章节，支持搜索正文、选中片段、预览配对、保存草稿和确认。编辑已有案例时通过查询参数 `caseId` 标识目标 |
| `/datasets/:datasetId/cases` | 案例筛选、分页、详情、编辑、停用和筛选结果导出。状态列只展示状态 |
| `/search` | 独立聊天页。支持连续查询、查看命中出处和打开案例详情 |

用共享布局承载顶部导航，用数据集布局承载面包屑和三个标签页。`/` 跳转到 `/datasets`，站点部署需支持直达子路由和刷新。将弹窗、状态标签和分页抽成共享组件。迁移现有 CSS 变量、布局尺寸和窄屏规则，替换原型的 HTML 字符串拼接、全局 DOM 事件委托与手动重绘。React 组件按文本渲染文档内容和检索摘录。

### 2. 对接数据和操作

- 建立类型化客户端，覆盖数据集、文档、切片、案例和检索操作。第一阶段从 `index.html` 提取 CNAS 样例作为开发数据，通过同一客户端接口提供模拟读写。正式环境切换到同源 Fastify API。原型的浏览器存储只用于演示，正式数据由服务端持久化。
- 标注页在组件状态中保存当前案例的元数据与双侧切片 ID，切换文档或章节时保留已选片段。离开未保存的标注页时提供保存、放弃和继续编辑。保存失败时保留编辑内容，确认前检查两侧都有片段，由服务端复核状态和数据集归属。
- 删除数据集时显示名称和删除范围，经用户确认后提交。服务端确认成功后再更新列表、统计和案例缓存，并从当前聊天会话清除对应结果卡片。请求失败时保留数据及界面状态，提供错误反馈。
- 聊天会话放在路由切换期间持续挂载的 React 状态中，新开或刷新页面时开始新会话。正式查询调用 `POST /api/v1/search`，提交 `query`，使用默认五条结果。按接口顺序渲染案例标题、数据集、命中源切片、全部关联测试需求和出处。空输入在客户端提示，空结果与请求故障分别显示，查询失败时保留输入。

### 3. 实施顺序与验收

1. 建立 React 路由和共享布局，接入模拟客户端，跑通新建、编辑、模拟上传、标注、确认、案例列表和聊天检索。
2. 接入正式 API，逐项替换模拟数据。验证导入中、解析失败、草稿保存失败、删除失败、检索失败及重试。生产构建使用正式客户端。
3. 用桌面和窄屏对照原型验证布局。用同一条配对案例检查双侧选择、未保存提示、确认后可检索、停用后无结果、删除后结果卡片清除。再验证子路由直达、页面刷新，以及聊天页与 API 在相同查询下的返回顺序一致。

## 演示验证

1. 在首页新建数据集，打开文档管理，在两栏分别模拟上传 DOCX。检查逐文件反馈、同名校验及重试。回到首页打开 CNAS 数据集。
2. 在标注工作台打开 CAN 示例草稿，检查两侧选区和配对，保存后人工确认。切换到案例列表查看状态和详情。重新打开页面检查状态是否保留。
3. 从顶部进入「案例检索」，用 `SJA1000` 查询。确认多片段命中在同一案例下显示，查看完整关联输出和出处，再打开案例详情。
4. 分别提交空白和无匹配查询。切回「历史数据集」，再进入「案例检索」，确认会话仍在。
5. 在数据集列表点击「删除」。先取消并检查数据与检索结果仍在，再确认永久删除。检查统计、历史对话和新查询结果，刷新后确认该数据集仍已删除。
