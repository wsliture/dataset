# 历史案例标注平台前端开发规格

本规格面向 React 前端开发、Fastify 接口联调和验收。业务目标以 [PRD](prd.md) 为准，DOCX 解析、持久化与检索以[技术规格](tech.md)为基础，页面布局和交互参考[离线原型](prototype/README.md)。首版另纳入单文档删除、筛选结果导出和表格行选择，相关接口按本规格联调。

## 1. 架构与运行环境

- 在独立的 dataset 仓库下以 `web/` 为前端工作目录，采用 Vite、React、TypeScript 和 React Router。部署支持 SPA 路由回退，子路由可直达和刷新，API 请求由同源 Fastify 处理。
- 页面通过类型化客户端访问 `/api/v1`。开发通过 Vite 代理、生产通过同源 Fastify 接入正式 API。业务数据由服务端持久化。
- 未提交的表单和选区保存在页面状态。聊天会话保存在持续挂载的根布局中，路由切换时保留，刷新或新开标签页时重置。文档、切片与查询摘录按纯文本渲染。

## 2. 页面与交互

| 路由 | 实现要求 |
| --- | --- |
| `/`、`/datasets` | 根路径重定向到列表。展示历史数据集、待确认案例和可检索案例三项统计。列表展示数据集名称、两类文档数量、各状态案例数量和更新时间。支持按名称查询、打开、新建、编辑和删除。名称去除首尾空白后必填，备注选填。删除弹窗列明数据集名称及永久删除范围。归档数据集可查看和删除，内部页面只读。 |
| `/datasets/:datasetId/documents` | 按「源需求／设计资料」「人工测试需求」展示文档。每栏可选多个 DOCX，逐文件显示上传、解析、成功或失败，失败项可使用原文件重试。详情按原文顺序展示章节、段落、条款、表格及解析告警，支持编辑切片文本和确认删除未被引用的文档。解析告警允许继续标注，人工测试需求导入成功后立即可选。 |
| `/datasets/:datasetId/annotation` | 两侧独立选择文档、章节并搜索当前文档正文。支持单片段、整表、表格行及本节批量选择。切换文档、章节或窄屏侧栏时保留双侧选区。已选区展示计数、出处、定位和移除操作。通过 `?caseId=` 编辑已有案例。 |
| `/datasets/:datasetId/cases` | 支持按标题或原文、状态、类别、测试对象、接口类型、场景和更新日期筛选。服务端分页，筛选变化时回到第一页。状态列仅展示状态，操作区提供编辑、停用及导出入口。详情按两侧展示关联内容与出处，使用 `?caseId=` 打开，支持检索页直达和浏览器返回。 |
| `/search` | 由顶部导航进入独立聊天页。支持连续查询和打开案例详情。按 API 顺序渲染数据集、案例标题、全部命中源切片和全部关联测试需求切片，各项显示文档、章节和定位。空输入在发送前提示。无匹配和服务故障分别反馈，失败时保留查询并允许重试。 |

数据集内部页面共用面包屑和「文档管理」「标注工作台」「案例列表」标签页。桌面工作台双栏并排，窄屏通过侧栏切换查看并持续显示双侧选择计数。宽表格可横向滚动。共用对话框、状态标签、出处和分页组件。对话框支持键盘关闭及焦点恢复，上传和检索反馈可由辅助技术读取。加载、空态和失败态分别呈现，提交期间禁用对应操作。

### 案例编辑与确认

- 表单包含标题、测试对象、多选类别、接口类型、场景、关键词、适用条件和标注说明。类别沿用原型的功能、性能、接口、可靠性／安全性、余量、边界、数据处理、恢复、强度和其他。
- 草稿允许字段和配对未填全。发布要求非空标题、非空测试对象、至少一个类别及双侧各至少一个有效切片，标注说明选填。确认弹窗展示完整配对，可直接点击「确认并发布」。服务端复核版本、数据集归属和发布条件。
- 界面「草稿」「已确认」「已停用」分别对应 `draft`、`published`、`withdrawn`。保存已确认或已停用案例的修改时转为草稿，再经人工确认发布。保存、发布或撤回失败时保留当前输入。版本冲突提示重新加载并核对，保留本地内容供比较。
- 页面跳转遇到未保存改动时提供保存、放弃和继续编辑。选择保存后，待成功才继续跳转。刷新或关闭标签页时使用浏览器退出提示。

## 3. 接口与状态同步

### 数据集、文档与切片

以下路径相对 `/api/v1`，文档和案例路径中的 `{dataset}` 表示 `/datasets/:datasetId`。

| 方法与路径 | 前端约定 |
| --- | --- |
| `GET /datasets`、`POST /datasets` | 查询列表、统计和新建数据集。 |
| `GET/PATCH/DELETE {dataset}` | 查看、编辑及永久删除数据集。 |
| `GET/POST {dataset}/documents` | 查询文档列表或以 multipart 导入单个文件，使用 `type` 和 `file`。类型为 `source` 或 `test_requirement`。上传成功返回解析结果，失败返回可展示原因。 |
| `GET/DELETE {dataset}/documents/:documentId` | 查看结构、切片及告警，或删除未被引用的文档。 |
| `PATCH {dataset}/documents/:documentId/slices/:sliceId` | 提交 `{ text, version }` 更新切片。成功后刷新正文、版本及受影响的整表。 |

表格行是服务端持久化的 `table_row` 切片，返回 `parentSliceId`、行顺序和行级 `sourceRef`。行文本保留列标题与单元格的对应关系。整表与所属行在同一案例内互斥，允许同时选择多行。选中整表时移除已选的所属行，选中行时移除其整表。本节批量选择以整表及独立切片为单位。服务端复核互斥规则。行参与编辑、索引、检索和导出。整表文本由行内容生成，行更新与受影响整表的文本及索引原子提交。

文档删除由服务端在事务内复核当前及历史案例引用，存在引用时返回 `409` 并提供可展示的阻塞案例。删除成功后刷新文档、切片和计数，工作台标记失效选区，移除后方可发布。数据集删除成功后刷新列表和统计、清除相关缓存，并从所有聊天轮次清除对应结果卡片。在途查询返回时同样剔除已删除数据集的结果。删除失败时保留页面状态和现有数据。

### 案例与导出

| 方法与路径 | 前端约定 |
| --- | --- |
| `GET/POST {dataset}/cases` | 筛选并分页查询案例，或新建草稿。 |
| `GET/PATCH {dataset}/cases/:caseId` | 查看详情或保存草稿。 |
| `POST {dataset}/cases/:caseId/publish` | 提交当前版本进行确认发布。 |
| `POST {dataset}/cases/:caseId/withdraw` | 提交当前版本进行停用。 |
| `GET {dataset}/cases/export` | 按当前生效的筛选条件导出全部有效且已确认的案例。 |

- 写入使用驼峰字段，类别使用 `categories: string[]`，配对使用 `sourceSliceIds` 与 `testRequirementSliceIds`，修改已有案例时提交 `version`。
- 列表筛选参数为 `q`、`status`、`category`、`testObject`、`interfaceType`、`scenario`、`updatedSince`、`page`、`pageSize`。列表响应为 `{ items, total }`，默认每页 20 条，更新时间降序，同时间按 ID 升序。日期采用浏览器本地日期的起始时刻并以 ISO 时间提交。
- 导出使用与列表相同的筛选语义，覆盖所有结果页。UTF-8 JSONL 每行一条案例，包含 `schemaVersion: 1`、数据集及案例 ID、案例版本、状态、元数据、双侧切片文本及出处。没有内容时提示无可导出案例。失败时保留筛选条件。

### 检索与异常

聊天页调用 `POST /api/v1/search`，发送去除首尾空白的 `{ query }`，采用服务端默认最多五条。按技术规格读取 `{ results }`，保留案例顺序。切片展示使用 `sliceId`、`text`、`documentId`、`documentName`、`sectionPath` 和 `sourceRef`。

| 结果 | 界面反馈 |
| --- | --- |
| `200` 且 `results` 为空 | 显示无匹配。 |
| `400` | 显示请求校验信息。 |
| `404` | 提示资源不存在或已删除。 |
| `409` | 按错误码展示版本或引用冲突。 |
| `503`、其他服务异常或网络故障 | 提示重试。查询失败时保留原查询。 |

资源错误返回 `{ code, message }`，文档引用冲突额外返回阻塞案例。上传错误在对应文件项显示，普通表单错误在对应页面显示。

## 4. 实施与验收

1. 通过正式 API 验证路由、文档预览、草稿、发布、案例详情和连续检索。在 requirements-manager 与 matrix-embedded-agent 均未启动时独立完成导入、标注和检索。
2. 用两类真实 DOCX 验证正文与表格交错、无标题、解析告警和出处。覆盖损坏、空内容、超限、重新导入，以及切片修改成功、版本冲突、已发布源切片更新失败。验证文档删除的当前及历史引用保护。
3. 用两个源切片配对三个测试需求切片，分别查询两个源切片，均返回同一案例、全部三个测试需求及出处。覆盖整表与行互斥、共享切片、空标注说明、发布必填项缺失、跨数据集引用、保存失败、停用后退出检索及 JSONL 跨页导出。
4. 对照聊天页和只读 API 的相同查询结果及顺序。覆盖空输入、无匹配、服务故障与重试、路由切换保留会话及刷新重置会话。验证取消删除、删除失败、删除成功，以及已删除数据集的在途查询返回不会恢复卡片。
5. 用桌面和窄屏核对布局、键盘操作、长文本、未保存提示、案例详情直达及子路由刷新。

本规格交付范围为独立 Web 及其同源 API。Phase 2 的实际接入、组织级权限和自动生成测试需求安排在后续版本。
