# 历史案例标注平台产品需求文档

## 1. 背景与目标

测试人员基于需求规格说明书、任务书、协议文档和接口说明等资料编写测试需求。历史项目中人工编写的测试需求可以为类似条款提供参考，但需要先明确哪些原需求或设计描述对应哪些测试需求，才能在新项目中检索和复用。

平台面向内部标注人员、检索验证人员和 Phase 2 接入开发人员。标注人员建立「原需求或设计描述 → 人工测试需求」配对案例。验证人员通过独立聊天页输入一段新需求，查看返回的历史条款和测试需求，判断样例是否能帮助生成 Agent 拆解可验证的条件、边界和预期结果。

首版在 `dataset/` 下独立运行，拥有独立的数据库和检索服务。交付 DOCX 导入与切片、多对多标注、案例管理、检索聊天页和只读检索 API。Phase 2 的实际接入、组织级权限和自动生成测试需求安排在后续版本。首版支持多个独立历史数据集，每个数据集管理一套文档基线及其文档和案例。

## 2. 产品功能

### 2.1 历史数据集与文档管理

- 首页展示数据集概览，支持按名称或已有文档基线查询。新建和编辑表单必填数据集名称，备注选填。
- 数据集详情提供「文档管理」「标注工作台」「案例列表」。数据集初始为「使用中」。列表支持删除，确认后永久移除数据集及其文档、案例和历史记录，并立即退出全局检索范围。既有归档数据集可查看或删除。

- 按「源文档」和「人工测试需求」分别导入，首版支持 DOCX。导入的人工测试需求默认已经通过评审。
- 按标题、条款或段落生成可编辑切片。导入后展示所属文档和切片内容，供标注人员检查、编辑和选择。
- DOCX 无法解析或未提取到可用文本时，提示失败原因，允许重新导入。

### 2.2 多对多标注与案例管理

- 提供双栏切片浏览和选择界面，左栏为源切片，右栏为测试需求切片。
- 一条案例关联至少一个源切片和至少一个测试需求切片，两侧切片均须属于该案例所在数据集，切片可在同一数据集内的多个案例中复用。发布前检查两侧是否均已选择切片。
- 案例状态为「草稿」「已确认」「已停用」，确认对应发布，停用对应撤回。标注说明可留空。案例列表支持按标题、原文、状态、类别、测试对象、接口类型、场景和更新日期筛选，并可查看详情。

### 2.3 检索聊天页

- 用户从顶部导航进入独立的「案例检索」聊天页，输入源需求、设计描述或接口标识，可在对话中连续查询并查看按相关性排序的案例。每条结果展示数据集、案例标题、命中的历史源切片、该案例关联的全部测试需求切片，以及各切片的文档、章节和定位，并可打开案例详情。
- 全局检索以使用中数据集内有效且已确认案例的源侧切片为匹配对象，采用关键词和语义相似度联合排序。多个切片命中同一案例时，合并为一条案例结果。默认最多返回五条符合相关性要求的案例。
- 聊天页分别提示空输入、无匹配和查询失败。查询失败时保留输入，便于重试。

## 3. 检索 API 与 Phase 2 接入

只读检索 API 与聊天页共用检索逻辑。相同案例库状态下，相同查询文本和返回条数应得到相同的结果及顺序。

| 项目 | 产品约定 |
| --- | --- |
| 请求 | 必填查询文本，可选最大返回条数，省略时最多返回五条 |
| 成功结果 | 按相关性排序的案例列表。每条包含数据集标识和名称、案例标识和标题、命中的源切片、案例关联的全部测试需求切片，以及各切片的所属文档 |
| 无匹配 | 查询成功并返回空列表 |
| 请求无效 | 明确指出查询文本为空或返回条数无效 |
| 服务异常 | 返回可与请求无效及无匹配区分的服务错误 |

后续由 `matrix-embedded-agent` Phase 2 在构建测试需求生成上下文时，以新识别的源需求或设计描述查询 API。Agent 参考历史案例中的条件、边界和预期结果，依据当前源文档编写测试需求。无匹配或服务不可用时，Phase 2 沿用现有生成流程。平台与 `requirements-manager` 和 `matrix-embedded-agent` 的接入边界为检索 API。

## 4. 验收与检索效果验证

| 场景 | 验收标准 |
| --- | --- |
| 数据集管理 | 新建两个数据集，分别管理文档基线与案例。取消删除时保留数据。确认后数据集及其文档、案例和历史永久删除，并从检索和当前对话记录中移除 |
| DOCX 导入 | 分别导入两类文档，按标题、条款或段落生成切片。编辑后的切片可直接用于标注。人工测试需求导入后可直接选择 |
| 多对多配对 | 用两个源切片和三个测试需求切片发布一条案例。分别查询两段源描述，均能返回该案例及三个测试需求切片。已有切片可用于另一条案例。标注说明留空时仍可发布 |
| 案例状态 | 草稿、已停用、引用无效和已归档数据集的案例均无法通过聊天页或 API 查询。任一侧缺少切片时，案例无法发布 |
| 返回一致性 | 同一查询和返回条数在两个入口得到相同案例及排序。多个源切片命中同一案例时，该案例只出现一次 |
| 独立运行 | 在 `requirements-manager` 和 `matrix-embedded-agent` 均未启动的环境中完成导入、标注、发布和查询 |
| 异常反馈 | 空输入、无匹配、DOCX 解析失败及查询服务故障均有明确且可区分的反馈 |

离线交互原型使用预置 CNAS 摘录、模拟 DOCX 上传及本地关键词检索，正式版验收依据本节的解析与混合检索要求。

检索验证人员建立带人工相关性判断的查询集，覆盖同义改写、边界条件、接口描述和无匹配输入。首轮验证记录以下结果。

- **前五条命中率**。在存在相关案例的查询中，前五条结果至少包含一条人工判定相关案例的查询占比。
- **无匹配误返回率**。在人工判定无相关案例的查询中，仍返回至少一条案例的查询占比。
- **代表性失败样例**。记录查询文本、预期案例、实际返回结果及人工判断理由。

Phase 2 接入的量化门槛在首轮基线测评后确定。
